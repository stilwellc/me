Digital · SecMCPHub on GitHub ↗

A monthly security review
that writes itself.

Security leaders spend the first week of every month rebuilding the same slides from three systems that don’t talk to each other. SecMCPHub is a set of Claude Code skills that pull those systems over the Model Context Protocol (MCP) and render one self-contained HTML report, in a single command.

the build · shape

Skills, a template, and two mapping tables.

The bundle is deliberately small. Two skills: /security-report does the refresh, /rewrite-dashboard rebuilds the renderer on the rare occasion the UI changes. One HTML template whose data and rendering live in separate script blocks, so a refresh only ever touches data. A rolling KPI history for sparklines and deltas, and two JSON maps that do the real work: CWE → risk category, and IR project → risk.

the run

Pull, compute, cross-reference, render.

The skill pulls from each configured MCP source, vulnerability findings in parallel batches, GRC paginated, incidents by project. It computes what a reviewer actually asks for: trend deltas against the history buffer, mean time to remediate, SLA compliance, and a weighted composite risk grade.

the proof · one view

Three reports become one view.

The part that makes it a dashboard instead of three reports. Findings are mapped to risk categories through CWE, incidents supply evidence against the same risks, and the two are chained into attack paths that show where the control gap is, so a control weakness, the vulnerabilities that exploit it, and the incidents that already did all appear in one view.

the call

No vendor, no server, on purpose.

Every organization runs a different vulnerability scanner, GRC platform, and ticketing system. The skills assume the three categories of source and nothing about the vendors: MCP tool names and field shapes are edited in one place. The report itself is one file with no server and no build step, so it can be shared and archived like any other document.
