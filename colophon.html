Colophon · how this site is built

Hand-built.
No framework, no build step.

Fifteen HTML files, one stylesheet, one script, six font files, and a line-screen engine drawn on a canvas. It is served as static files from GitHub Pages, sets no cookies, and runs no analytics.

the ground

Eggshell, ink, one accent.

The page is a sheet of paper: an off-white ground, near-black ink, three greys for hierarchy, hairlines for registration, and one orange for the one thing on the page that is alive. Type is Geist for reading, Geist Mono for labels and values, and Bricolage Grotesque, set light, for the display sizes and the name in the masthead. Two widths: forty-four rems for prose, sixty for objects.

the line screen

Every header is the same machine.

A band is a grid of cells, four pixels on a side. A word is drawn to an offscreen canvas and sampled into that grid to make a mask. A picture is sampled the same way, at twice the resolution, stretched for local contrast and given an edge channel, so a photograph becomes a field of dashes and a glyph becomes squares. Cells that carry nothing get a filler dot, which is why every band is a full rectangle whatever it holds.

The dots are bodies. Each has a home in the current field and a target in the next; pairs are made by angle around the centre so the picture turns into the word without crossing itself. A page load gathers the bodies in from outside the band, a change explodes them and remakes them, leaving a page scatters them, and a light wind from a flow field gives the flight some weight. The whole thing is one file with no dependencies.

Pictures never leave the browser. The file is read into the canvas and forgotten when the page closes.

the build

Files on a disk, served as they are.

There is no bundler, no template layer and no client router. Each page carries its own markup, the shared stylesheet, and the shared script; a cache-busting version on those two files is the whole deployment story. Photographs ship with width and height and a small variant for phones. Social cards are rendered by a small page in the repository with the same line-screen code, once, and committed.
